# 投币口 / AIGC 影视流程复盘与下一项目基础规则 v1

## 这轮暴露的根问题

1. 人物不是“好看但泛”的问题，而是缺少可测的 face DNA 和阶段状态锁。小满旧图失败的原因不是年龄写得不够小，而是脸型、发型、表情机制和手势都落在小川同一区间。
2. 白模不是参考草图，而是把 AIGC 当渲染器时的空间输入。白模如果重复、遮挡错误、比例不准，后续真实图会继承这些错误。
3. 分镜不是 20 张概念图，而是 5-6 分钟影片的生产栅格。188 张只是最低可执行版本，复杂动作和心理转折仍需要继续加中间帧。
4. 声音不能等画面完成后再补。对白、停顿、环境声、SFX、音乐和剪辑时间必须和分镜表共享同一时间线。
5. pure 图和 annotated 图必须分开。pure 图给模型，不能有制作标注；annotated 图给人和流程，承担判断、返工和沟通。

## 下一项目默认流程

### 0. 设定章节先行

- 无论项目由剧本、参考视频、图片还是口头点子发起，第一步永远是生成设定章节。
- 设定章节必须覆盖所有人物、道具、车辆、动物、核心符号、场景、环境、风格和阶段状态。
- 设定章节必须明确哪些资产已经有官方锁图，哪些还处于 `needs_setting_lock`。
- 设定章节确认前，不允许进入镜头排产、白模、关键帧生成、AIGC 视频包或最终剪辑。
- 参考视频只负责时序、机位、运动和剪辑功能；角色、道具、场景和风格必须由设定章节锁定。
- 剧本项目先从剧本抽设定；视频复刻项目先从视频抽设定；图片项目先把图片归档为候选锁图。

### 1. 剧本/视频单元

- 每个新项目先写 `03_story/scripts/director_shooting_script.md`，由剧本决定镜头单位，而不是由生成图片倒推连续性。
- 必须建立 `07_shots/video_units.json`：一个 video unit 可以是一张关键帧、多个连续关键帧、一组 montage、一对转场或一个一镜到底段落。
- 必须建立 `07_shots/transition_edges.json`：所有转场都作为边记录，包含前镜头结束状态、后镜头开始状态、写入哪个提示词。
- 必须建立 `06_previs/camera_manifests/video_unit_camera_manifest.json`：按 unit 写机位、轴线、屏幕方向、白模/Blender/playblast 门禁。
- `07_shots/shot_list.csv` 里的每张关键帧必须写 `video_unit_id`、`video_unit_type`、`keyframe_role`、`unit_prompt_path`、转场边和是否需要白模。
- `07_shots/video_prompts_by_unit/` 是视频阶段优先读取的提示词目录；逐卡 `video_prompts/` 只能作为当前关键帧在所属 unit 内的引用说明。
- 多图 unit 必须显式写 `图1`、`图2`、`图3` 的顺序、人物、空间关系和连接方式。
- 所有图生视频 / AIGC 视频生成提示词必须写入硬性声音规则：只要音效/环境声，不要音乐、不要 BGM、不要 soundtrack。最终剪辑配乐单独规划，除非用户对某个项目明确覆盖这条规则。
- 片头、地图机关、标题序列类一镜到底，必须先设计镜头旅行路线：真实位移、前中后景视差、尺度变化和终点大揭示。除非导演明确要锁定机位，否则不能只做“建筑原地升起”的静态机关。
- 拆 AIGC 视频镜头包时，必须生成一个人类优先入口：`AIGC_VIDEO_PROMPT_INDEX.md` 总索引 + 每镜 `PROMPT_ONLY.md`。外部网站投喂优先看 prompt-only；`AIGC_VIDEO_GENERATION_BRIEF.md` 是完整机器/QA包，不应成为导演找提示词的唯一入口。
- 每次新增生成图或重拆 video unit 后，prompt-only 必须重新从“当前 ordered generated anchors”生成，逐条列出最新 official/R-pass 图。旧的 `Existing Unit Prompt` 如果没有包含新增图片，只能作为历史参考，不能作为当前主提示词。
- 资产锁结构默认是“全局一份 + 每镜 active 列表”：包根目录保留 `_global_asset_locks/`，每个 video unit 写 `active_asset_locks.json` 和 prompt-only 中的 active-lock 行，只列本镜实际出现或必须约束的人物、道具、车辆、动物、符号、场景锁。黑场、纯天空、标题安全位、抽象水纹等无角色/道具镜头应显示 `none`。
- 只有为了单个镜头离线转交给外部工具时，才允许复制 per-unit `asset_locks/`；这种复制必须标注为 redundant/self-contained packaging，不能让无关角色或道具看起来像出现在本镜。
- 如果是一镜到底，默认先做：首帧 + 尾帧 + 必要关键帧 + Blender 白模/高模或代理模型 + 相机位移动画 + playblast 内录/渲染，再让 AIGC 做风格化渲染。
- 对抗性测试：调换图1/图2后提示词仍成立则失败；one-take 能被拆成互不关联的小视频则失败；montage 被写成平滑连续摄影则失败；转场只写在孤立提示词里而没有 edge 数据则失败。

### 1.5 智能抽帧、差异筛选和资产晋升

- 参考视频项目必须先做两层本地分析：第一层是全片保底频率抽帧，确保每个镜头/video unit 的首帧、尾帧和常规时间点都被看见；第二层是差异性加帧，用镜头切换、画面相似度、运动幅度、构图变化、人物/道具/场景状态变化来补候选帧。
- 截图和相似度/运动/构图分析主要在本地磁盘完成，默认只把候选清单、差异理由、联系表和少量必要代表帧带入对话，避免消耗大量 token。
- 本地分析只能作为候选排序器，不是最终导演判断。它对镜头边界、相似度、运动、明暗色彩、构图变化比较可靠；对“这张是否叙事关键”“这个表情是否最重要”“这个人物是否最像锁图”必须结合影视判断、设定锁和必要的视觉复核。
- 抽帧密度可以较高，但抽出来的帧只是 `candidate_reference_frame`，不是项目最终资产。不能因为候选帧多，就机械生成同样数量的新图。
- 真正晋升为新资产的标准是“画面区别足够大”或“叙事/镜头功能极其重要”：构图、机位、人物姿态、动作阶段、道具状态、场景状态、故事节拍、转场逻辑有明显变化；或者它是一个完整镜头/video unit 的首帧、尾帧、关键转折帧。
- 对一镜到底、慢推、慢摇、慢动作保持、Nemo 船长这类连续段落，默认只晋升首帧 + 尾帧 + 中间 1-2 张最关键过渡帧。连续运动由精准提示词和参考视频承担，不靠大量近似帧堆出来。
- 对群像、动作、快速剪辑、道具变化、场景切换或强转场段落，可以晋升更多关键帧，但每一张都必须写清 `difference_reason`，说明它和前一张在画面或叙事上为什么不同。
- 被晋升的帧必须进入正式生产链：分配稳定 `item_id`、绑定 `video_unit_id` 和原视频 timecode、生成提示词、生成 pure 新图、记录 `output_path`、完成 identity/scene/prop QA。只有完成这些步骤后，它才算项目资产。
- 候选帧生成 pure 新图后，必须同步写回：候选队列状态、生成资产 manifest、P1 联系表、受影响 video unit 的 prompt-only 文件或统一 addendum。新图只存在于 `outputs/` 目录不算已经进入后续 AIGC 视频合同。
- 如果实际生图时对提示词做了安全改写、人物/道具修正或二次重生，必须保存最终使用版本或 prompt addendum，不能让旧的候选提示词继续作为唯一记录。
- 生图 QA 不能只看构图。还要检查：无文字/无水印、人物锁一致、道具/车辆/动物/符号不漂、没有随机徽章/logo/政治军事符号、动物伙伴没有换物种、画幅尺寸可被统一预览。
- 如果候选截图是有风险的局部机位或容易误读的身体特写，保留镜头功能并安全改写成全身/侧向/动作状态帧，不照搬危险机位。
- 若生成工具返回非目标画幅，记录尺寸；预览和视频合成阶段用统一画布 fit/pad，不能为了凑比例拉伸人物和道具。
- 预览视频必须由“已有合格资产 + 新晋升且已生成的资产”重建。如果只完成了密集抽帧和候选分析，没有生成新图并入库，最终预览张数不应被称为已扩展。
- 如果一次智能抽帧后最终张数没有变化，必须明确原因：没有候选被晋升；或晋升了但尚未生成新图；或生成了新图但尚未写入资产清单。不能让“抽帧密度增加”和“最终资产增加”混为一谈。
- 不能用全片统一 FPS 代替镜头判断。下一轮视频复刻默认以 `shot/video_unit` 为分析对象，每个 unit 独立决定期望分析密度：静态/黑场/天空 hold 约 1-2fps；慢推/慢变化/肖像 hold 约 2-4fps；人物入场、群像、道具变化、车辆、水花、光效和转场约 6-8fps；极短且快速变化的转场/飞行器/水花可局部到 8-12fps。
- 分析密度不等于生成密度。即使一个镜头按 8-12fps 分析，也只生成首尾帧、关键转折帧和真正提供新构图/新动作/新道具状态/新转场功能的帧。
- 候选帧不能只和前一帧比。必须和当前镜头已有 official anchors、已生成扩展资产、首尾帧和设定锁一起比，判断它是否真的补了“已有资产没有的信息”。
- 候选进入生图前必须先分为 `P1/P2/P3`：P1 是下一小批真正要生成的关键差异帧；P2 是预览仍然稀薄时再补；P3 是已覆盖、重复、一镜到底或只需要参考视频承担的帧。
- 生图前必须看 P1-only 联系表，删除字幕变化、标题安全位变化、空天空微变、边界误选和近重复帧。只有 P1 通过后才创建 prompt/参考板/输出路径。
- 如果当前环境没有 `ffmpeg/cv2/moviepy/av` 等解码能力，不能声称完成了高密度抽帧；只能标记为基于现有采样帧的 provisional audit，并写明哪些 unit 需要补装解码工具后再做 6-12fps 复核。
- 如果导演指出“一闪而过的人物/道具/转场没抓住”，下一步不是盲目多生图，而是先做源帧率级别的边界复核：用 OpenCV/帧差计算灰度、颜色直方图、边缘/构图变化，标出单帧或两三帧 flash insert，再用 PySceneDetect 交叉验证。2fps 或 4fps 联系表只能当初筛，不能当最终边界判断。
- 如果参考视频存在 20-25 秒的连续长开场或一镜到底短片段，不要机械拆成很多 1-3 秒小镜头。默认拆成 2-3 个 AIGC 可操作长段，每段保留参考视频片段、首尾/关键闪帧锚点、精准运动提示词和 active asset locks。

### 1. 故事和阶段锁

- 先拆故事阶段：开场、进入、冲突前、冲突中、事故后、逃跑、异化、结尾。
- 每个阶段必须写明角色心理、表情、衣服干净度、道具状态和环境状态。
- 后续分镜、白模、图像 prompt、音频 cue、剪辑表都必须绑定 `story_stage`。

### 2. 人物设计

- 每个角色先写小传、轮廓、五官、服装来源、习惯动作、表情库和禁区。
- 每个角色必须先建立官方锁图：导演最满意的正脸/首次亮相图优先成为 `official_identity_lock`，后续不得重新发明脸。
- 角色锁图不能只靠文字描述。多角色、远景、小脸、奔跑、合照、montage 镜头必须引用已批准锁图作为 identity anchors。
- 同一角色后续可以改变表情、动作、光线和阶段状态，但脸型、年龄感、发型、关键饰品、服装识别和体态锚点不能漂移。
- 容易混的角色必须写 pairwise contrast：例如主角 vs 弟弟、老大 vs 跑腿。
- 亲属可以有相似感，但必须能在缩略图里靠脸、头发、体态、手势区分。
- 如果剧情导致性格、表情、服装、泥灰、伤痕、道具位置变化，必须追加阶段人设。

### 2.5 场景、道具和资产锁

- 主要场景必须建立 `official_scene_lock`：空间结构、色彩、光源、时代信息和环境锚点必须稳定。
- 主要道具、车辆、动物、符号必须建立 `official_prop_lock`：造型、颜色、材质、尺寸关系和佩戴/持有位置必须稳定。
- 任何后续镜头如果换了角色脸、服装、场景结构、核心道具造型或车辆设计，即使画面好看，也只能标为 continuity fail。
- 关键帧状态必须拆分为构图通过、无文字通过、角色身份通过、道具连续性通过、场景连续性通过和视频可用通过，不能用一个笼统 QA pass 盖过去。

### 3. 白模

- 原则上每张 micro storyboard 都应有独立白模图。
- 可以共用白模的情况只有两类：同一机位、同一构图、位移非常小，且故事只需要通过 prompt 改动微表情、手势、UI 或光效。
- 小位移也必须在 prompt 里写明“在这个构图下发生了什么位移”，不能让模型自己猜。
- 白模 QA 必须检查：缺图、空图、低对比、相邻重复、角色遮挡、比例、轴线、主体位置、环境锚点。

### 4. 真实图生产

- 先生成角色 S0 clean 基础人设，再生成后段脏乱/受伤/异化阶段人设。
- 每个场景先做 1-3 张真实图试产，验证人设、空间、清洁度、风格，再批量铺开。
- 真实图生成顺序：A 级关键帧 -> start/end frame -> 高风险动作中间帧 -> B/C 级补帧。
- 每张图必须输出 pure 和 annotated 两版。pure 不含制作标注；annotated 后处理叠加必要字段。
- 真实图进入视频生成前必须通过 identity/scene/prop continuity QA。群像图和大合照如果人物脸漂，必须先返修，不能带病进入视频模型。

### 5. 音频

- 导演需要判断哪些剧情需要对白、旁白、系统声或设计沉默。
- 台词必须写角色口气、潜台词、停顿、麦克风距离和处理方式。
- 音效/音乐单独表格化，不写进图片 prompt，靠 `visual_range` 和时间点关联分镜。
- guide WAV 可以先用本地 TTS 和程序化声音对时，最终再替换为正式表演和声音设计。

### 6. Animatic

- 在真实图未全量完成前，用白模/已完成 pure 图混排成 PPT 式 animatic。
- animatic 必须按 `approx_time` 或剪辑表持续时间输出，并合成 guide WAV。
- 每轮真实图替换后重建 animatic，检查故事节奏、空间连续性和声音点位。

## 对传统影视流程的取舍

保留：

- 人物小传、服装 continuity、场景调度、白模/预演、分镜 animatic、声音 cue sheet、剪辑节奏表。

调整：

- AIGC 不适合靠现场临场调度补救，必须把角色状态、空间、光线和动作路径预先写死。
- 传统分镜可以省略的“中间状态”，在 AIGC 里往往必须拆成图。
- 传统拍摄可以用演员统一角色，AIGC 必须用 face DNA、阶段人设和 QA 维持角色。

放弃：

- 为了“镜头多样性”频繁换轴、换构图、换风格。
- 把声音当后期装饰。
- 用一张漂亮概念图替代可生产的分镜体系。
