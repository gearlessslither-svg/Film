# 投币口 / 01_AIGC 白模扩展计划 v2

## 核心判断

现有 21 张白模只能支撑 macro storyboard，不能支撑 188 张 micro storyboard。当前规则升级为 panel-level whitebox：默认每一张 MSB 分镜都必须有一张对应白模。只要同一环境内存在不同机位、人物站位变化、运动路径、围堵关系、首尾帧衔接，就必须先补白模定位，再生成 pure 图。

更严格地说，本项目把 AIGC 当作“根据白模渲染真实画面”的渲染器使用，所以白模不是示意图，而是构图、比例、空间关系和人物 blocking 的结构合同。白模不够准确时，不能为了让白模成立而修改原分镜意图；必须修白模。

白模不是美术图，而是空间事实：

- 人在哪里
- 摄像机在哪里
- 入口和出口在哪里
- 谁挡住谁
- 主体朝哪里运动
- 前景/中景/背景怎么分层
- 下一张图如何接上

## 白模需求判定

| 情况 | 是否需要新增白模 |
|---|---|
| 纯环境建立，沿用已有机位 | 必须，除非被明确合并为同一张 intentional hold |
| 同一场景换角度 | 必须 |
| 三人或七人站位关系变化 | 必须 |
| 围堵、推搡、失衡 | 必须 |
| 石块、手、身体和遮挡关系 | 必须 |
| 逃跑方向和追兵距离 | 必须 |
| 走廊纵深、电话亭位置 | 必须 |
| 8-bit 横版固定舞台 | 每格仍输出白模；可共用舞台轴线，但角色/UI 状态必须逐格体现 |
| 单人近景表情 | 必须；表情、手、道具、光效变化要在白模里有可读结构 |
| 角色灰墙设定图 | 不需要 |

## 白模输出规则

- 白模图输出到 `whitebox_renders_v2/`。
- 文件名使用 `WB2_<scene>_<number>_<description>.png`。
- 默认每张白模只对应一个 MSB panel。
- 共用白模是例外，不是默认。允许共用的前提是构图不变、故事动作只发生在表情/手指/小道具/光效/UI 状态上，并且在 `whitebox_composition_reuse_plan.csv` 中写清 prompt delta。
- 白模必须可被纯图提示词引用。
- 白模联系表输出到 `whitebox_renders_v2/contact_sheets/`。

## 白模和 pure 图关系

1. 先看 `exports/whitebox_expansion_plan.csv`。
2. 188 张 MSB panel 全部 `whitebox_required=yes`，必须有对应 whitebox v2。
3. 生成 pure 图时使用该白模作为结构参考，不把白模线条或灰模材质带进最终图。
4. pure 图跑偏时，先判断白模是否不够细；如果不够，补白模，不要只改 prompt。

## 跑偏优先修正

| 跑偏现象 | 先修什么 |
|---|---|
| 同一场景入口位置乱跳 | 新增/修正 scene master whitebox |
| 人物阵营左右反了 | 新增对峙白模并标明站位 |
| 围殴动作乱 | 拆白模为围住、推搡、失衡三张 |
| 石块动作英雄化 | 增加石块前景、弯身、遮挡冻结白模 |
| 逃跑方向不清 | 增加 escape path 白模序列 |
| 电话亭位置漂移 | 增加电话亭远景、中景、特写白模序列 |
| 8-bit 舞台变 3D | 固定 orthographic side view 白模 |
