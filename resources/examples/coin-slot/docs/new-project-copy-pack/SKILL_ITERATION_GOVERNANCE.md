# Skill 统一迭代治理手册（禁止项目内私自演化）

目标：把跨项目发现的有效改进，统一沉淀到 `1主3子 Skill`，避免每个项目重复造轮子、规则漂移。

---

## 1. 总原则

1. **流程只在 Skill Pack 演进，不在项目里演进**。
2. 项目允许改“参数”，不允许改“流程定义”。
3. 所有流程变化必须能跨项目复用，才能进入 Skill Pack。
4. 无证据的改动不上线；无回归的改动不合并。

---

## 2. 哪些改动允许留在项目里

允许（项目局部）：

- 角色名、场景名、镜头编号、风格关键词、音乐段落边界等项目特定参数。
- 项目私有素材路径与资源文件。

不允许（必须上收）：

- 新 QA 判定逻辑
- 新门禁状态定义
- 新的输入/输出字段契约
- 新的回退机制
- 新的“何时可晋升”规则

如果你不确定，默认按“上收 Skill Pack”处理。

---

## 3. 统一迭代流程（强制）

1. **发现问题**：在项目中定位失败现象。
2. **记录提案**：填写 `templates/SKILL_ITERATION_PROPOSAL.md`。
3. **验证复现**：至少在当前项目复现一次。
4. **抽象升级**：提炼为跨项目规则（去掉项目专有命名）。
5. **修改 Skill Pack**：更新对应 `SKILL.md`（主/子）。
6. **回归检查**：至少用 2 类项目场景验证（剧情向 + 音乐向）。
7. **发布记录**：写入 `SKILL_CHANGELOG.md`，并标注影响范围。

---

## 4. 变更分级（便于决策）

- **P0 阻塞级**：导致交付中断或大量返工，必须优先上收。
- **P1 质量级**：明显提升稳定性或可读性，安排到下一轮上收。
- **P2 效率级**：主要提升效率，放入批量优化队列。

---

## 5. 版本与发布约定

- Skill Pack 使用 `MAJOR.MINOR.PATCH`：
  - `MAJOR`：契约不兼容变更
  - `MINOR`：新增能力且兼容
  - `PATCH`：规则修正与文案补强
- 每次更新都要在 `SKILL_CHANGELOG.md` 记录：
  - 变更点
  - 触发项目
  - 影响 Skill
  - 是否需要迁移动作

---

## 6. 执行检查清单（每轮必过）

- 是否有项目内新增流程定义未上收？
- 是否更新了对应 Skill 文档？
- 是否补了迭代提案与变更日志？
- 是否完成最少两类项目回归？
- 是否更新了新项目手册中的相关步骤？

任一项为“否”，本轮迭代不得视为完成。
